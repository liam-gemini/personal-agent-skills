# Documentation Policy

Write stable domain terminology to the project's `CONTEXT.md`; exclude implementation details and temporary plans.

Create or propose an ADR only when the decision is costly to reverse, surprising without context, and based on a real trade-off.

Keep project-specific constraints in `AGENTS.md`, domain language in `CONTEXT.md`, and architectural decisions in `docs/adr/`. Do not move confidential project content into the personal-skills repository.

Before creating any additional documentation category, prove that an existing project artifact cannot hold the information cleanly.
